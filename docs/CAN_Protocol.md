# CAN 总线 ID 与通信协议

本文按当前固件整理 CAN1 板间/上位机通信和 CAN2 本地电机总线。除另行注明外，报文均为 **11 位标准数据帧**，CAN 波特率为 **1 Mbps**，单帧最多 8 字节。应用协议没有额外的序号或校验字段；CAN 控制器负责链路层校验。

## 1. 总线分工与接线

| 总线 | 用途 | MCU 引脚 | 当前连接对象 |
| --- | --- | --- | --- |
| CAN1 | 底盘/云台板间命令与状态；可与上位机共享 | PD0 RX、PD1 TX，AF9 | 两控制板 CAN 收发器及系统上位机链路 |
| CAN2 | 当前控制板的电机反馈、电流命令；底盘板还接功率计 | PB5 RX、PB6 TX，AF9 | 本板电机控制器和底盘功率计 |

MCU 的 CAN_TX/CAN_RX 是收发器侧逻辑信号，不能直接接 CANH/CANL；CANH、CANL 应接到 CAN 收发器的总线端。检查两端终端电阻、收发器供电及共地。底盘板和云台板的 CAN2 使用了相同的一组标准电机 ID，分别服务本板设备；不要把两块板的 CAN2 总线误当成板间总线。板间通信走 CAN1。

CAN1、CAN2 均配置正常模式、1 Mbps、自动总线关闭开启、自动重发关闭。应用启动时 CAN1 从滤波器 bank 0 开始，CAN2 从 bank 14 开始；当前 BSP 的零掩码过滤器接收所有标准 ID，再按“总线 + ID”分发给注册回调。因此，协议表中的“未使用/预留” ID 仍可能进入 CAN RX，但没有相应的应用处理逻辑。

## 2. CAN1：板间与上位机协议

CAN1 的多字节值采用 STM32 小端序。`int16_t` 为二进制补码；`float` 为 32 位 IEEE-754 单精度。表中的发送方、接收方描述当前应用方向；上位机可以按 CAN1 网络拓扑监听或发送对应报文。

| ID | 方向 | DLC | 数据布局与含义 | 当前固件状态 |
| --- | --- | ---: | --- | --- |
| `0x111` | 云台/控制端 → 底盘 | 8 | `int16 vx`、`int16 vy`、`int16 vz`、`int16 power_pct`。`vx/vy`：mm/s；`vz`：每 LSB 为 0.001 rad/s；`power_pct`：百分比 ×100，当前保留。 | 底盘注册并用于速度控制。哨兵急停保留值：`vx = -32768`。云台在 DBUS 控制源下发送；也可将 `0x120` 原样转发为此 ID。 |
| `0x112` | 底盘 → CAN1 网络 | 8 | `data[0..1]` 为实际功率 `int16`，单位 W×100，小端序；`data[2..7]` 为 0。 | 底盘周期发送；当前底盘/云台通信模块没有为此 ID 注册接收回调。 |
| `0x113` | 控制端 → 底盘 | 8 | `float speed`（mm/s）、`float steer_angle`（rad），均为小端序。 | 底盘通信层已注册并解包；当前哨兵底盘控制未使用该模式数据。 |
| `0x115` | 控制端 → 底盘 | 8 | 4 个小端序 `int16`：`vx`（mm/s）、`vy`（mm/s）、`gimbal_angle`（每 LSB 0.001 rad）、`custom`（保留）。 | 底盘通信层已注册并解包；当前哨兵底盘控制未使用该模式数据。 |
| `0x119` | 底盘 → 云台 | 8 | `data[0..3]` 为 `float omega_z`（rad/s，逆时针为正）；其余字节为 0。 | 底盘发送，云台接收并用于状态反馈。 |
| `0x120` | 雷达/上位机 → 云台 | 8 | 与 `0x111` 相同的 4 个小端序 `int16` 字段。 | 云台接收；S2 选择 CAN 控制源时，在控制调度中原样转发为 `0x111`。 |
| `0x121`、`0x125` | 控制端 → 云台 | 8 | 两个小端序 `float`：`yaw_inc`、`pitch_inc`，单位 rad；依次从 `data[0..3]`、`data[4..7]` 发送。 | 云台接收为增量角度命令；`0x125` 是带射击模式的对应命令。 |
| `0x122` | 云台 → CAN1 网络 | 8 | 两个小端序 `float`：yaw、pitch 角速度，单位 rad/s。 | 云台周期发送。 |
| `0x123`、`0x127` | 控制端 → 云台 | 8 | 两个小端序 `float`：`yaw_abs`、`pitch_abs`，单位 rad。 | 云台接收为绝对角度命令；`0x127` 是带射击模式的对应命令。 |
| `0x124` | 云台 → CAN1 网络 | 8 | 两个小端序 `float`：yaw、pitch 当前角度，单位 rad。 | 云台周期发送。 |
| `0x126` | 云台 → CAN1 网络 | 8 | 8 字节发射机构状态数据，字段由调用方定义。 | 通用发送接口已实现；当前哨兵云台控制流程没有调用该接口。 |
| `0x129` | 控制端 → 云台 | **4** | `data[0] = shoot_switch`、`data[1] = retreat`，`data[2..3]` 保留。有效组合：`FF 00` 开启摩擦轮和拨弹轮；`FF FF` 仅运行摩擦轮；`00 FF` 拨弹轮反转；其他组合停止。 | 云台只接受 DLC 至少为 4 的命令。该 ID 当前为接收命令。 |
| `0x130` | 云台 → CAN1 网络 | 8 | 4 个小端序 `uint16`：yaw、pitch、roll 原始编码值和 `interval`。 | 预留 V2 反馈发送接口；当前哨兵云台控制流程没有调用。 |
| `0x139` | 云台 → CAN1 网络 | 8 | 两个小端序 IEEE-754 `float32`：`yaw_deg`（`data[0..3]`）、`pitch_deg`（`data[4..7]`），单位均为度。 | 云台周期发送融合后的 IMU 欧拉角；此帧只包含 yaw 和 pitch，不包含 roll。 |
| `0x233` | 云台 → CAN1 网络 | 8 | 4 个小端序 `int16`：四元数 `q0/q1/q2/q3 × 30000`；解码时各字段除以 30000。 | 云台周期发送 IMU 四元数。 |

`0x31` 和 `0x39` 在云台通信头文件中标为达妙 IMU 请求/响应 ID，但当前未注册回调、未发送，也没有在此项目中定义其数据布局；接入前需另行约定协议。

CAN 接收回调运行于 RX 中断上下文，通信层只校验长度、复制字段并设置更新标志；控制逻辑在主调度中读取快照。`0x111`、`0x120`、`0x121` 等帧必须发送完整 DLC=8；只有 `0x129` 的接收协议规定 DLC=4。当前 BSP 的 `bsp_can_tx()` 固定发送 DLC=8。

## 3. CAN2：哨兵底盘电机与功率计

底盘板的 CAN2 ID 和电流组帧如下。电机反馈为 8 字节 DJI 电机反馈格式。

| ID | 方向 | 设备/槽位 | 数据格式 |
| --- | --- | --- | --- |
| `0x201` | 电机 → 底盘 | 右驱动 M3508 反馈 | DJI 8 字节反馈帧 |
| `0x202` | 电机 → 底盘 | 左驱动 M3508 反馈 | DJI 8 字节反馈帧 |
| `0x205` | 电机 → 底盘 | 左转向 GM6020 反馈 | DJI 8 字节反馈帧 |
| `0x206` | 电机 → 底盘 | 右转向 GM6020 反馈 | DJI 8 字节反馈帧 |
| `0x212` | 功率计 → 底盘 | 电池电压、电流和保留字段 | 下方单独说明 |
| `0x200` | 底盘 → 电机 | 槽 0：右驱动；槽 1：左驱动 | 8 字节电流组帧：`[右驱动 int16][左驱动 int16][0][0]` |
| `0x1FF` | 底盘 → 电机 | 槽 0：左转向；槽 1：右转向 | 8 字节电流组帧：`[左转向 int16][右转向 int16][0][0]` |

## 4. CAN2：哨兵云台电机

云台板使用同一类 DJI 电机反馈和电流组帧；这些 ID 与底盘板的 CAN2 配置分开使用。

| ID | 方向 | 设备/槽位 | 数据格式 |
| --- | --- | --- | --- |
| `0x201` | 电机 → 云台 | 左摩擦轮 M3508 反馈 | DJI 8 字节反馈帧 |
| `0x202` | 电机 → 云台 | 拨弹轮 M2006 反馈 | DJI 8 字节反馈帧 |
| `0x203` | 电机 → 云台 | 右摩擦轮 M3508 反馈 | DJI 8 字节反馈帧 |
| `0x205` | 电机 → 云台 | 大 yaw GM6020 反馈 | DJI 8 字节反馈帧 |
| `0x206` | 电机 → 云台 | 小 yaw GM6020 反馈 | DJI 8 字节反馈帧 |
| `0x207` | 电机 → 云台 | pitch GM6020 反馈 | DJI 8 字节反馈帧 |
| `0x1FE` | 云台 → 电机 | 槽 0：大 yaw；槽 1：小 yaw；槽 2：pitch | 8 字节电流组帧：`[大 yaw int16][小 yaw int16][pitch int16][0]` |
| `0x200` | 云台 → 电机 | 槽 0：左摩擦轮；槽 1：拨弹轮；槽 2：右摩擦轮 | 8 字节电流组帧：`[左摩擦 int16][拨弹 int16][右摩擦 int16][0]` |

### DJI 电机反馈与电流组帧

电机反馈 8 字节数据场按大端序解析：

| 字节 | 字段 | 类型/单位 |
| --- | --- | --- |
| `D0..D1` | 编码器角度 | `uint16`，高字节在前 |
| `D2..D3` | 转速 | `int16`，高字节在前；电机协议原始转速值 |
| `D4..D5` | 电流 | `int16`，高字节在前；电机反馈原始值 |
| `D6` | 温度 | `uint8`，℃ |
| `D7` | 保留 | 当前驱动解析不使用 |

发送电流帧中，每个电机占两个字节，为二进制补码 `int16`，高字节在前；例如 `-1` 编码为 `FF FF`。没有使用的槽位填 0。一个 CAN ID 可同时携带多个电机命令，因此帧中槽位顺序必须与表格一致。

### 功率计反馈 `0x212`

底盘接收 8 字节小端序数据：

| 字节 | 字段 | 类型/缩放 |
| --- | --- | --- |
| `D0..D1` | 电池电压 `bat_v` | `uint16`，0.01 V/LSB |
| `D2..D3` | 电池电流 `bat_i` | `uint16`，0.01 A/LSB |
| `D4..D5` | 保留 0 | `uint16`；当前功率计固件发送 `0xFFFF` |
| `D6..D7` | 保留 1 | `uint16`；当前功率计固件发送 `0xFFFF` |

固件按 `power_W = (bat_v / 100) × (bat_i / 100)` 计算电池侧功率。该反馈只在底盘板应用中接收。

## 5. 调试与源码对应
